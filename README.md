# RepoTether

GitHub / Gogs などのリポジトリ一覧を元データにして、ローカルフォルダと紐づけて扱う個人用ツール。

プロジェクトを手で登録する手間をなくすのが目的。リモートにあるものがそのまま管理対象になる。

## 範囲 (v1)

柱は 3 本。どれも同じデータを別の角度から見るもので、取り込みは 1 つ、表示が 3 つ。

| 柱 | 見せるもの | 答える問い |
|---|---|---|
| **履歴** | コミットと Claude セッションを全リポジトリ横断で時系列に並べる。日報はここから切り出す | いつ、何をやったか |
| **グラフ** | 活動の図 (プロジェクト別ヒートマップ、週ごとの作業量の推移) | どこに時間を使っているか、どれが止まっているか |
| **ローカルの状態** | 未コミット、未 push、main に入っていないブランチ、放置期間 | いま何が取り残されているか |

git のコミットグラフ (ブランチのツリー表示) は主役にしない。GitKraken や VS Code の Git Graph で見られるため。
入れるとしても、ローカルの状態の画面から個別リポジトリについて開く補助表示にする。

### データの取り込み (土台)

- **リポジトリ一覧** — GitHub / Gogs の API から取得してキャッシュする
- **ローカルとの紐づけ** — 決めたルート (例: `C:\Repos\<owner>\<name>`) を探索し、remote URL で照合する
- **git** — 各リポジトリのコミット (自分の分)、作業ツリーの状態、ブランチ
- **Claude Code のセッション** — `~/.claude/projects/<パスを変換した名前>/*.jsonl`。
  フォルダ名が作業フォルダのパスに対応するので、紐づけ済みのリポジトリにセッションを割り当てられる。
  ドライブ文字の大文字・小文字が混ざる (`C--Repos-...` と `c--Repos-...`) ので正規化してから照合する

### 操作

クローン、VS Code、ターミナル、エクスプローラーで開く。

## やらないこと

サーバーモード、マルチユーザー、認証、チケット管理。
(PMManage が広がりすぎた反省。必要になってから考える)

## 開発

Tauri v2 + SvelteKit (adapter-static) + TypeScript。パッケージは pnpm。

```sh
pnpm install
pnpm tauri dev     # デスクトップアプリ起動
pnpm check         # 型チェック
pnpm tauri build   # 配布バイナリ生成
```

ポートは LPortMan の台帳に登録済み: Vite dev `11420` (Tauri の devUrl)、HMR `11421` (`TAURI_DEV_HOST` 指定時のみ)。

## メモ

- Gogs の API (`/api/v1/user/repos`) は GitHub に近い形で、Gitea もこれを受け継いでいる。1 つのアダプタで両方に対応できる見込み
- セッションの要約を LLM で作るかは未定。使うなら無料の経路 (`claude -p` のサブスク枠 / ローカルの gemma) に限る。
  v1 は要約なしで、最後のやりとりを抜き出すだけでも成り立つ
- クローン導線・フォルダ起動は PMManage (`../PMManage`) のコードを流用元にできる
- 開発サーバーの起動は LocalLauncher (`../LocalLauncher`) の担当で、ここでは扱わない
- 技術スタックは未定
